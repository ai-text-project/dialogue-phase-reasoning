# Navigation Architecture Definition

**Architecture Version:** v1.0 (Draft)

---

# Purpose

This document defines the navigation architecture of the Research Entry Package.

The objective is not to describe the repository itself.

Instead, this document defines how first-time visitors progressively understand the research program through a structured navigation process.

Accordingly, this document focuses on cognitive navigation rather than repository organization.

---

# Background

As the Dialogue-Phase Reasoning repository has grown, the number of research assets has increased significantly.

These assets include:

- flagship papers
- methodology documents
- governance
- terminology systems
- research architecture
- research maps
- comparative observations

Although each asset has a clearly defined role, first-time visitors may find it difficult to determine where to begin.

The Navigation Architecture therefore defines a coherent exploration pathway through the research program.

---

# Design Principle

The Navigation Architecture is based on one fundamental principle:

Visitors should first understand the research program before exploring the research environment.

Accordingly, navigation should follow conceptual understanding rather than repository hierarchy.

---

# Navigation Philosophy

The navigation sequence should gradually increase conceptual depth.

Rather than exposing every repository component immediately, each step prepares visitors for the next level of understanding.

Navigation therefore functions as a projection layer between external researchers and the internal research environment.

---

# Navigation Layers

The proposed navigation consists of the following layers.

```text
Repository Overview
        │
        ▼
Research Entry Package
        │
        ▼
Research Overview
        │
        ▼
Core Research Assets
        │
        ▼
Research Architecture
        │
        ▼
Research Environment
        │
        ▼
Repository Exploration
```

Each layer introduces only the concepts necessary for understanding the following layer.

---

# Navigation Flow

Within the Research Entry Package, the recommended reading sequence is:

```text
README

↓

One-page Overview

↓

Reading Path

↓

Core Assets

↓

Research Repository
```

After entering the repository, visitors may continue according to their interests.

Examples include:

- flagship papers
- research architecture
- methodology documents
- terminology systems
- governance
- research maps

The Navigation Architecture therefore provides orientation rather than prescribing a fixed reading order.

---

# Relationship to Repository Structure

The Navigation Architecture is independent of the repository hierarchy.

Repository organization defines where research assets are stored.

Navigation Architecture defines how visitors gradually understand those assets.

Accordingly, these two structures should evolve independently while remaining mutually consistent.

---

# Relationship to Research Architecture

Research Architecture describes the organizational structure of the research program.

Navigation Architecture describes the exploration process through that structure.

The former models the research environment.

The latter models visitor understanding.

These two architectures therefore complement each other.

---

# Future Evolution

The Navigation Architecture may later support multiple navigation modes.

Examples include:

- Academic Research Path
- Enterprise Research Path
- Student Learning Path
- Collaboration Entry Path

Each path should preserve the same underlying navigation principles while adapting to different audiences.

---

# Scope

This document defines navigation principles only.

It does not describe:

- research theories;
- individual methodologies;
- governance mechanisms;
- terminology systems;
- repository implementation details.

These topics belong to other documents within the repository.
