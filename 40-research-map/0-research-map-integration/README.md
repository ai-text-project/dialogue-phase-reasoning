# Purpose

This domain provides a structural orientation for understanding `40-research-map`.

The Research Map contains multiple forms of research activity and research records, including:

- Emergence Observations
- Open Questions
- Research Notes
- Meta Cases
- Methodological observations
- Operational observations
- Role and handover observations
- Architectural observations

These assets were not created as parts of a single predefined hierarchy.

They emerged gradually through research activity.

As a result, the repository structure alone does not fully explain how these domains relate to one another.

This integration domain therefore provides:

> **a structural map for understanding relationships already present within the Research Map without reorganizing the existing research assets.**

---

# Core Principle

The Research Map should not be interpreted as a simple folder hierarchy or a single research pipeline.

The current structural observation indicates that it functions more accurately as:

> **a recursive research environment in which observation can generate higher-order observation, methodological organization, operational projection, structural recognition, and renewed interpretation of the Research Space itself.**

The integration therefore follows the principle:

> **Relationship Externalization rather than Repository Reorganization**

# Four Relationship Types

The Structural Integration identifies four major relationship types.

## 1. Developmental

Observation may become increasingly organized through:

```text
Observation
    ↓
Observation Criteria / Protocol
    ↓
Methodological Formation
```

This represents a developmental possibility, not a mandatory sequence.

---

## 2. Transformational

Methodological knowledge may be projected into operational forms:

```text
Methodological Knowledge
          ↓
Operationalization
          ↓
Protocol / Procedure
          ↓
Operational Asset
```

This represents functional transformation rather than movement to a higher abstraction level.

---

## 3. Connective

Research activities may be connected through interfaces:

```text
Research Output
      ↓
Role Interface
      ↓
Handover
      ↓
Next Research Activity
```

These interfaces preserve responsibility boundaries while supporting continuity.

---

## 4. Recursive

Observation may ultimately change how the Research Space itself becomes legible:

```text
┌──────────────────────────────────────────┐
│                                          │
│              RESEARCH SPACE              │
│                    │                     │
│                    ▼                     │
│               OBSERVATION                │
│                    │                     │
│                    ▼                     │
│         HIGHER-ORDER OBSERVATION         │
│                    │                     │
│                    ▼                     │
│          STRUCTURAL RECOGNITION          │
│                    │                     │
│                    ▼                     │
│        RELATIONSHIP EXTERNALIZATION      │
│                    │                     │
│                    ▼                     │
│       RESEARCH SPACE REINTERPRETATION    │
│                    │                     │
│                    └─────────────────↺   │
│                                          │
│            RECURSIVE FEEDBACK            │
│                                          │
└──────────────────────────────────────────┘
```

Research Space is therefore both:

- an environment in which observation occurs,
- and a structure that may itself become newly observable.

# Position of Meta Cases

`03-meta-cases` occupies an important position within this model.

Meta Cases preserve higher-order observations in which research activity itself may become observable.

Observed objects include:

- Research-Space organization,
- observation processes,
- observation criteria,
- methodological structures,
- methodological governance,
- operational transformations,
- role interfaces,
- and architectural integration processes.

Meta Cases should therefore not be understood only as an archive of unusual cases.

They function provisionally as an important:

> **Higher-Order Observation Domain**

within the Research Map.

This does not mean that Meta Cases constitute a formal architectural layer.

# Repository Structure and Structural Position

The Research Map contains repository domains such as:

```text
00-emergence-observations
01-open-question-index
02-open-questions
03-meta-cases
05-research-notes
```

These folders represent repository placement and recording responsibility.

The Structural Map represents relationships among research functions.

Therefore:

> **Repository Position ≠ Structural Position**

The existing folder structure should not be reorganized solely to reproduce the Structural Map.

# Structural Boundary

This integration does **not** claim that:

- the Research Map is a fixed hierarchy,
- all research activity follows one sequence,
- Meta Cases constitute a formal architectural layer,
- Methodological Governance is hierarchically superior to Methodology,
- Operationalization represents higher abstraction,
- Architecture is the terminal point of research development,
- `[MM]` has a finalized structural meaning,
- or the existing repository should be reorganized according to this map.

The integration externalizes observed relationships.

It does not prescribe a new repository architecture.
